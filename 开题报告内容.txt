Boot框架，数据库选用MySQL，系统将实现管理员与普通读者双角色权限管理。（二）选题拟研究解决的主要问题本课题拟研究解决以下主要问题：系统架构设计问题：如何设计合理的B/S架构，使系统同时支持Web管理后台与微信小程序端访问，确保两端数据同步与功能一致性。图书信息管理问题：实现图书信息的增删改查功能，支持按书名、作者、分类等多条件检索，并提供模糊匹配与分类筛选能力。借阅业务流程问题：设计图书借阅、归还的完整业务逻辑，自动更新图书可借状态，实现逾期判断与罚款计算功能。用户角色与权限管理问题：设计管理员和普通读者两种角色，实现登录验证和权限控制，确保不同角色拥有不同的操作界面和功能权限。数据统计与可视化问题：实现借阅量排行、图书流通情况、逾期统计等数据的统计与图表展示。高频借阅场景下的库存并发控制问题：在热门图书短时集中借阅场景下（如新学期教材借阅高峰期），多个读者可能同时提交同一本图书的借阅请求，需防止因并发操作导致的超借现象（即图书库存被减至负数），确保数据一致性与业务正确性。（三）内容提纲本毕业设计论文拟包含以下章节：引言：阐述选题背景、国内外研究现状、研究目的与意义。相关技术介绍：介绍B/S架构、Spring Boot、Vue.js）以及数据库技术（MySQL）等方面。技术预研：已初步学习了Spring Boot框架的基本使用方法，了解了Vue.js的前端开发模式，并对MySQL数据库的设计与操作进行了复习和巩固。同时，对微信小程序的开发流程和接口调用方式进行了初步研究。需求调研：参考了多篇同类系统的开题报告和设计论文，了解了在线图书借阅管理系统的常见功能模块和业务逻辑流程。（二）目前存在的难点及解决措施难点一：微信小程序端与Web管理后台的数据同步与接口统一解决措施：采用前后端分离架构，后端统一提供RESTful API接口，小程序端和管理后台共用同一套接口。使用Axios进行前后端交互，确保数据一致性和接口复用性。难点二：逾期罚款计算的精确性与业务逻辑复杂性解决措施：设计合理的罚款计算规则，在数据库层面记录每笔借阅的应还日期，通过定时任务或实时计算方式判断逾期天数，按照预设规则自动计算罚款金额，并支持读者在线缴纳操作。难点三：多条件模糊检索的性能优化解决措施：在数据库设计阶段为常用检索字段（如书名、作者）建立索引，使用SQL的LIKE语句实现模糊匹配。同时考虑在业务层面对检索结果进行分页处理，避免一次性加载大量数据影响响应速度。难点四：高频借阅场景下的库存并发控制解决措施：在数据库层面采用乐观锁机制控制库存并发。借阅操作执行时，通过UPDATE book SET stock = stock - 1 WHERE id = ? AND stock > 0语句保证库存不会被减至负数，并检查更新影响的行数来判断借阅是否成功；若影响行数为0，说明库存已被其他读者抢先借完，返回借阅失败提示。在应用层面，可考虑对热门图书的借阅操作引入Redis分布式锁（如Redisson），将同一本图书的并发借阅请求串行化处理，进一步降低超借风险。难点五：图书热榜的动态统计与查询性能优化解决措施：采用“定时计算+Redis缓存”的策略优化热榜查询性能。每日凌晨通过Spring的@Scheduled定时任务，从借阅记录表中聚合统计前一日的图书借阅量，将排行榜数据存入Redis的Sorted Set数据结构（以图书ID为member、借阅量为score）。读者端查询热榜时直接从Redis读取，避免高频查询对数据库造成压力。同时，在借阅记录表中为book_id和borrow_time建立复合索引，加速定时任务的统计查询。（三）预期成果完成一个功能完善的在线图书借阅管理系统，支持微信小程序端和Web管理后台。实现图书信息管理、多条件检索、借阅归还、逾期罚款、数据统计等核心功能。完成系统功能测试与性能优化，确保系统稳定可靠运行。（四）界面设计方案本系统界面设计遵循“简洁、清晰、高效”的原则，面向两类用户群体（普通读者与管理员）分别设计差异化的视觉与交互体验。1. 整体风格与配色方案整体风格采用扁平化设计，以白色为底，搭配蓝色系（主色#1890FF）作为主色调，营造专业、可信的阅读氛围。卡片式布局承载图书信息，辅以柔和阴影提升视觉层级感。字体以无衬线字体为主，保证不同设备上的阅读舒适度。2. 微信小程序端（读者端）核心页面布局读者端面向移动场景，强调操作的轻量与便捷，核心交互路径为：首页 → 检索 → 借阅 → 个人中心。首页：顶部为全局搜索框（支持书名/作者模糊检索），中部以轮播图展示“热门推荐”或“新书上架”，下方以双列瀑布流展示图书列表，每个图书卡片包含封面图（缩略图）、书名、作者和状态标签（“可借”为绿色、“已借出”为灰色）。检索结果页：顶部保留搜索框，下方提供分类筛选标签（横向滚动，按文学/科技/教育等分类），结果以列表形式展示，每项右侧显示“借阅”按钮，若图书已全部借出则按钮置灰不可点击。图书详情页：展示图书封面大图、完整书名、作者、ISBN、分类、简介、总库存/可借数量，底部固定放置“立即借阅”按钮（库存充足时高亮可点，库存为0时置灰）。个人中心：顶部展示用户头像、昵称和当前借阅数量，下方以列表菜单形式呈现“我的借阅”“我的罚款”“修改密码”等功能入口。在“我的借阅”子页面中，每本图书显示借阅日期和应还日期，逾期图书以红色高亮显示，并标注应缴罚款金额，提供“在线缴纳”按钮。3. Web管理后台（管理员端）核心页面布局管理后台面向桌面端，强调信息概览与批量操作效率。仪表盘：顶部为统计卡片行（总馆藏、在借量、逾期量、今日借阅量），中部左侧以柱状图展示“近7日借阅趋势”，中部右侧以饼图展示“图书分类占比”，下方为“借阅排行榜”表格（显示排名、书名、借阅次数）。图书管理页：左侧为分类树（可展开折叠选择分类），右侧为图书列表表格（包含序号、书名、作者、ISBN、库存、可借数、操作列），顶部提供组合搜索框（书名+作者+分类联动），支持Excel批量导入和导出图书数据。借阅管理页：以表格展示所有在借记录，包含读者姓名、图书名、借阅日期、应还日期、状态（正常/逾期），每行提供“催还”按钮；顶部统计卡片显示当前逾期总数及预计罚款总额。读者管理页：以表格展示所有注册读者信息，支持按姓名或学号检索，管理员可启用/禁用读者账号。4. 关键交互流程说明读者借阅流程：首页检索图书 → 点击图书进入详情页 → 查看可借状态 → 点击“立即借阅”按钮 → 弹出确认对话框（显示书名和应还日期）→ 确认后借阅成功并跳转至“我的借阅”列表。管理员处理逾期流程：仪表盘查看逾期统计卡片 → 点击进入借阅管理页 → 筛选“逾期”状态记录 → 点击单条记录的“催还”按钮 → 系统自动通过微信小程序模板消息向读者发送催还通知。管理员上架新书流程：进入图书管理页 → 点击“新增图书”按钮 → 弹出表单（填写书名、作者、ISBN、分类、库存、简介等信息）→ 提交后列表实时刷新显示新书。三、基本工作思路（一）研究方案与方法本课题采用软件工程的瀑布模型作为开发方法论，按照“需求分析→系统设计→系统实现→系统测试”的流程推进工作。具体方法如下：文献研究法：通过阅读相关学术论文和技术文档，掌握系统开发所需的技术知识和设计方法。需求调研法：参考同类系统的功能设计，明确本系统的功能需求和性能需求。原型开发法：采用迭代开发方式，先实现核心功能模块，再逐步完善辅助功能。测试验证法：通过功能测试和性能测试验证系统各项功能的完整性和稳定性。（二）技术路线系统架构：采用B/S架构，前后端分离开发模式。后端技术：Spring Boot框架 + MyBatis ORM + MySQL数据库。前端技术：Web管理后台使用Vue.js + HTML/CSS/JavaScript；移动端使用微信小程序。开发工具：IntelliJ IDEA（后端）、VS Code（前端）、MySQL Workbench（数据库）、微信开发者工具（小程序）、Redis（缓存服务器，用于热榜数据缓存）。运行环境：JDK 1.8、Maven 3.x、Tomcat（内置于Spring Boot）。（三）重点解决的问题系统整体架构设计与数据库设计，确保系统可扩展性和数据一致性。图书借阅、归还的业务流程设计与状态管理。双角色（管理员与读者）的权限控制与界面分离。逾期判断与罚款计算功能的准确实现。图书库存的并发控制，防止热门图书在高频借阅场景下出现超借。图书热榜的高效统计与缓存策略，确保查询性能。四、工作进度安排进度安排（包括时间划分和各阶段主要工作内容）2026.05.25—2026.06.03：拟定题目、选题；2026.06.04—2026.06.15：下达及接受任务书；2026.06.16—2026.06.30：查阅资料、系统方案设计、设备选型、撰写开题报告。2026.07.01—2026.07.31：完成前后端基础框架搭建及数据库设计；2026.08.01—2026.12.31：完成所有功能设计，完成论文并交第一稿；2027.01.01—2027.03.20：完善设计细节及测试，修改论文并交最终稿；2027.03.21—2027.04.15：查重及准备答辩。参考文献[1]
